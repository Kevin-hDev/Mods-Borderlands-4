# 常见问题

## Mod Settings 能在 Epic Games 版上运行吗？

它从未在 Epic Games 版上试过，只在 Steam 版 1.11.0-4906557 上测试过。如果你试了，请在[Nexus 页面的 Bugs 标签页](https://www.nexusmods.com/borderlands4/mods/388?tab=bugs)告诉我们结果，并附上 SDK 日志。

## 合作模式呢？

它从未在合作模式下试过。Mod Settings 不通过游戏网络发送或接收任何内容：它只修改你电脑上的模组。某个模组在合作模式下的表现取决于该模组。

## SDK 控制台还有用吗？

有。「模组」是通往相同设置的另一个入口：在一边做的更改会出现在另一边，而且「模组」每次打开都会重新读取所有内容。要开启或关闭 Mod Settings 本身，需使用控制台。

## 如何关闭 Mod Settings？

在 SDK 控制台中：按 `~`，再输入 `mods`，然后选择 Mod Settings。在「模组」中它的页面上，「已启用」开关不会响应：如果从那里关闭，它会在你使用页面时切断页面。关闭后，「模组」入口仍留在菜单中，因为它来自资源包；打开「模组」时，会显示「MOD SETTINGS 无响应」。要让它消失，还需移除资源包 `mod-settings_999_P.pak`。

## 移除 Mod Settings 后，我的设置会怎样？

不会有任何变化。你的模组设置由 SDK 保存在 `...\Borderlands 4\sdk_mods\settings\` 中，每个模组一个文件，并会一直保留在那里。移除 Mod Settings 的两个文件：暂停菜单和主菜单会恢复原样。

## 为什么某个模组在「模组」中没有显示全部设置？

「模组」显示每个模组向 SDK 声明的内容，与控制台相同。有自己设置窗口的模组，可能只向 SDK 声明了部分设置，或者一个都没有。见[故障排除](TROUBLESHOOTING.zh.md)。

## 为什么 Mod Settings 没有自己的设置？

Mod Settings 只是通往 SDK 控制台的另一个入口，仅此而已：它显示并修改每个模组声明的内容，不在其上添加自己的设置。每多一个功能，就多一样可能在游戏更新时损坏、或与它显示的模组冲突的东西。而且，模组作者在控制台中试过自己的模组，也就等于在「模组」中试过了。

## Mod Settings 会让游戏变慢吗？

菜单关闭时，它什么都不做。每次打开「模组」时，它都会重新读取模组的设置（游戏加载暂停菜单或主菜单时也会先读取一次），这会让游戏短暂停顿：安装 22 到 29 个模组时，每次启动游戏后的第一次为 0.2 到 0.35 秒，之后为几毫秒到 50 毫秒（游戏内实测）。

## Mod Settings 会连接互联网吗？它安全吗？

它不会连接互联网。页面和 Python 模组通过一个只监听你电脑的小型服务通信，该服务会拒绝浏览器中打开的网页发出的请求。详情见[工作原理](HOW_IT_WORKS.zh.md)。

## 我可以复用它的代码吗？

可以，需遵循 Mozilla Public License 2.0 许可证：见 [README](README.zh.md) 的「许可证」部分。
