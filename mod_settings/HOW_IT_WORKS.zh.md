# 工作原理

Mod Settings 由两个文件组成：一个界面资源包 `mod-settings_999_P.pak`，在游戏菜单中绘制「模组」；一个 Python 模组 `mod_settings.sdkmod`，读取并修改 SDK 的模组。本页说明两者之间发生了什么，让你知道 Mod Settings 会改动什么、不会改动什么。

<img src="site/images/pause-menu.jpg" width="1200" height="986" alt="游戏的暂停菜单，「模组」入口处于选中状态">

## 一项设置的传递过程

1. 资源包用多了一个「模组」入口的副本替换游戏的暂停菜单和主菜单。
2. 你打开「模组」时，页面借用游戏「选项」界面的组件：开关、滑块、下拉列表、按键和标签页。因此它拥有游戏的外观、音效和操作方式。
3. 页面通过你电脑上的本地服务，向 Python 模组请求模组列表。
4. Python 模组读取 SDK 的模组列表以及每个模组声明的选项，与 SDK 控制台的模组菜单相同。
5. 你更改设置时，页面发送新值。Python 模组检查它是否在该模组接受的范围内，然后把它交给该模组，与控制台完全相同。
6. SDK 将设置保存到 `...\Borderlands 4\sdk_mods\settings\` 中该模组的文件里。

<img src="site/images/mod-page.jpg" width="1600" height="839" alt="「模组」中一个模组的页面：它的标签页、滑块、开关和说明面板">

Mod Settings 自己不保存任何设置：每个值都存在声明它的模组中，「模组」只是它的一种显示方式，与控制台相同。

## 更改何时生效

- **模组会立即收到新值**。它如何使用、何时使用，取决于该模组。
- **拖动滑块时**，最多每 100 毫秒发送一次值，且最后一个值一定会发送。
- **更改会立即保存**，滑块除外：滑块在你关闭「模组」时，或下一次更改其他设置时保存。如果游戏在此之前崩溃，这个滑块的最后一个值会丢失。

## 每次打开「模组」时

「模组」每次打开时都会重新读取模组列表及其设置；游戏加载暂停菜单或主菜单时，也会先读取一次。因此，在别处（SDK 控制台或某个模组的窗口中）更改的设置，会在下一次打开时显示出来。

这次读取会让游戏短暂停顿，且只发生在菜单中：安装 22 到 29 个模组时，每次启动游戏后的第一次为 0.2 到 0.35 秒，之后为几毫秒到 50 毫秒（游戏内实测）。菜单关闭时，Mod Settings 什么都不做。

## 游戏文件及其更新

- 资源包含有游戏暂停菜单和主菜单的副本，基于已测试的版本 1.11.0-4906557 制作。游戏会加载它们，代替自己的菜单。
- 如果游戏更新改变了这些菜单，资源包仍保留旧副本：在 Mod Settings 更新之前，这些菜单可能缺少新内容或表现异常。移除资源包即可让游戏恢复自己的菜单，你的设置不会改变。
- 其他同样替换暂停菜单或主菜单的模组会与 Mod Settings 冲突：两者只有一个能生效。
- 这些副本属于 Gearbox Software 和 2K。因此资源包只在 Nexus 上提供，不在 GitHub 仓库中。

## 本地服务，以及为什么拒绝网页

页面和 Python 模组通过你电脑上的一个小型服务通信。

- **它只监听你的电脑**（`127.0.0.1`，端口 38791）。不会向互联网或游戏网络发送任何内容，合作模式下也一样。
- **它拒绝网页**。它拒绝来自浏览器中打开的网页的任何请求。如果没有这项拒绝，你在游戏时访问的网站就可能向该服务发送请求，更改你的模组设置。只有游戏界面和你自己电脑上的程序能使用它。
- **每个请求都很小并经过检查**：请求内容最多 512 字节，超出模组接受范围的值会被拒绝。
- 如果其他程序已在使用这个端口，Mod Settings 不会启动，SDK 日志会记录这一点（见[故障排除](TROUBLESHOOTING.zh.md)）。

## 为什么有限制

「模组」为每个列表设有上限：模组、选项、可选项的数量，以及文字长度。没有这些上限，一个声明数千个选项的模组可能让页面变得巨大，并在每次打开时让游戏卡住。超出限制时，「模组」会隐藏或截断超出的部分，而 SDK 控制台会显示它们。具体数值见[模组作者指南](MOD_AUTHORS.zh.md)的「限制」部分。
