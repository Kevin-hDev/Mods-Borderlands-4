# 故障排除

找到你看到的情况。每一条都说明原因和解决办法。

Mod Settings 在 SDK 日志中的行以 `[ModSettings]` 开头。日志文件是 `...\Borderlands 4\OakGame\Binaries\Win64\Plugins\unrealsdk.log`，每次启动游戏都会重写：请在重新启动前复制它。如果这里的内容都帮不了你，请在[Nexus 页面的 Bugs 标签页](https://www.nexusmods.com/borderlands4/mods/388?tab=bugs)提交报告，并附上这个文件。

## 致玩家

### 菜单中没有「模组」入口

**原因**：「模组」入口来自资源包 `mod-settings_999_P.pak`。它不在 `...\Borderlands 4\OakGame\Content\Paks\` 中，或者另一个模组也替换了暂停菜单或主菜单：两者只有一个能生效。

**解决办法**：把资源包放到正确位置；它在 Nexus 文件「Mod Settings Paks」中。如果另一个模组改动了这些菜单，先移除它试试。

### 「模组」显示「MOD SETTINGS 无响应」

**原因**：页面在，但 Python 模组没有响应。Python SDK 未安装，`mod_settings.sdkmod` 不在 `...\Borderlands 4\sdk_mods\` 中，Mod Settings 在 SDK 控制台中被关闭，或者它未能启动。

**解决办法**：安装 SDK 和 `mod_settings.sdkmod`（见 [README](README.zh.md)）。打开 SDK 控制台（按 `~`，再输入 `mods`），确认 Mod Settings 已启用。否则，在日志中查找 `[ModSettings]`：

- 没有任何一行：SDK 没有加载 Mod Settings，或者它已被关闭；
- `START_FAILED port_in_use_or_refused`：另一个程序正在使用端口 38791，或者 Mod Settings 刚被关闭，还没有释放该端口。等待几秒，然后在控制台中关闭再重新开启 Mod Settings；
- `START_TIMEOUT`：在控制台中关闭再重新开启 Mod Settings；
- 其他 `START_FAILED` 行：在控制台中关闭再重新开启 Mod Settings。如果它再次出现，请附上日志报告此问题。

### 「模组」显示「模组列表尚未就绪」

**原因**：Python 模组有响应，但还没有读完模组列表。如果每次打开都出现这条消息，并且日志中有 `MODEL_TOO_BIG`，说明你的模组列表太大，「模组」无法显示。

**解决办法**：关闭「模组」再重新打开。如果这条消息再次出现，请附上日志报告此问题。

### 「模组」显示「按键捕获需要 MOD SETTINGS」

**原因**：更改按键要经过 Python 模组。它没有响应，或者还没有发送模组列表。

**解决办法**：稍等片刻，然后重试。如果这条消息再次出现，见上文「MOD SETTINGS 无响应」。

### 「模组」显示「更改被拒绝」并带有一个数字

**原因**：更改没有生效，该行重新显示模组中的值。数字说明原因：

- 0：Mod Settings 没有及时响应，或者它已被关闭（见上文「MOD SETTINGS 无响应」）；
- 409：页面中仍是旧的设置列表，例如在「模组」打开期间有设置发生了变化；
- 403：此设置无法更改；
- 400：该值超出了模组接受的范围；
- 503：游戏中待处理的更改太多。

**解决办法**：重新进行更改。如果仍被拒绝，关闭「模组」再重新打开。

### 某个模组不在列表中

**原因**：「模组」显示 Python SDK 的模组，与 SDK 控制台中的相同。以其他方式安装的模组，例如单独的 `.pak` 资源包，不会出现在这里。超过 64 个模组时，之后的不显示。

**解决办法**：查看该模组是否在 SDK 控制台中（按 `~`，再输入 `mods`）。如果它在控制台中却不在「模组」中，请附上日志报告此问题。

### 某个模组显示「无设置」，或设置比它自己的窗口少

**原因**：「模组」显示该模组向 SDK 声明的内容，与控制台相同。有自己设置窗口的模组，可能只向 SDK 声明了部分设置，或者一个都没有。

**解决办法**：在该模组自己的窗口中设置它，按其作者说明的方式打开该窗口。如果其作者希望它在「模组」中完整显示，[模组作者指南](MOD_AUTHORS.zh.md)会告诉作者如何做。

### 崩溃后某个滑块回到了旧值

**原因**：滑块在你关闭「模组」时，或下一次更改其他设置时保存。在此之前崩溃，会丢失它的最后一个值。

**解决办法**：重新设置它，然后关闭「模组」。

### 在主菜单中，按 Esc 会打开「退出游戏」

**原因**：在主菜单中，「模组」绘制在菜单页面内。此时对游戏来说，Esc 表示「退出」，它在自己的代码中打开这个窗口，模组无法拦截。在暂停菜单中，Esc 正常工作。

**解决办法**：点击「取消」，或使用「返回」和「关闭」。

### 游戏更新后，暂停菜单或主菜单表现异常

**原因**：资源包含有这些菜单的副本，基于已测试的游戏版本制作。改变这些菜单的更新会让副本过时（见[工作原理](HOW_IT_WORKS.zh.md)）。

**解决办法**：移除 `mod-settings_999_P.pak`，等待 Mod Settings 更新。你的设置不会改变。

### 游戏是其他语言，「模组」却显示英语

**原因**：「模组」的文字有英语、法语和简体中文版本。其他语言下仍显示英语。设置的名称和说明由各模组提供，通常是英语。

**解决办法**：没有能改变这一点的设置。如果你希望「模组」使用你的语言，请在[Nexus 页面的 Posts 标签页](https://www.nexusmods.com/borderlands4/mods/388?tab=posts)中提出。

## 致模组作者

[模组作者指南](MOD_AUTHORS.zh.md)说明「模组」如何显示你的选项。这里只列出症状，以及指南中解答它们的部分。

### 你的模组的某个选项没有出现

**原因**：「模组」不支持它的类型，它的值无效，它超出了某项限制，或者它被隐藏了。

**解决办法**：在日志中查找 `[ModSettings] MODEL_BUILT` 这一行。它的计数 `unsupported`、`truncated` 和 `failed_mods` 说明了哪些内容被略去，是所有模组合计的总数。指南在「检查你的模组」中解释了这一点，另见「选项类型」和「限制」。

### 你的所有选项都在「通用」标签页中，或者它们的顺序会变化

**原因**：不使用 `build_mod(options=[...])` 时，SDK 收集模块中选项的顺序可能会变化，并且会忽略你的 `GroupedOption` 和 `NestedOption`。

**解决办法**：把你的选项传给 `build_mod(options=[...])`。见指南中的「整理你的选项」。

### 你的 `on_change` 函数读到的是旧值

**原因**：SDK 在改变值之前调用它。

**解决办法**：从它的 `value` 参数读取新值。见指南中的「更改如何传到你的模组」。

### 拖动你的模组的滑块时，游戏卡顿

**原因**：滑块每秒最多发送十次值，每次都会调用你的 `on_change` 函数。

**解决办法**：保持它轻量：不要写文件，也不要做耗时的查找。

### 有你的模组时，「模组」打开得很慢

**原因**：每次打开时，「模组」都会调用每个模组列出选项的函数（`iter_display_options`），这在游戏线程上进行。如果你的函数做了繁重的工作，游戏会在它运行期间卡住，而「模组」可能会显示之前的列表，直到下一次打开。

**解决办法**：保持这个函数轻量：让它只返回你的选项，不做任何计算或加载。
